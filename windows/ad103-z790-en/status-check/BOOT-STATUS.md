# AD103 boot evidence and live state

Run `D:\AI\bench\Check-AD103-Unlock.cmd` and approve the Windows administrator prompt. This reads firmware and prints JSON. It does not run a workload or touch GPU registers.

`handoff_state=UNLOCK_VERIFIED_AT_EFI_HANDOFF` means the modified EFI application completed its transaction, safe-return check, and final `GuZ790ReadyForWindows()` hardware verification, then published a volatile runtime UEFI variable immediately before starting Windows. The variable has attributes 6 (boot service + runtime), never the nonvolatile bit. The reader rejects persistent variables, wrong versions, wrong GPU fingerprints, and incomplete check flags. An absent variable, access failure, skipped transaction, or failed attempt never means LOCKED. The writer must actually execute on a subsequent unlock boot before a receipt can exist.

`live_gpu_state=UNKNOWN` is deliberate. This receipt records the final EFI check. It cannot guarantee that Windows has not subsequently reset/reinitialized the GPU, nor is it cryptographic attestation against an administrator rewriting firmware variables. Sleep/resume, hibernation, fast startup, and driver updates must not be inferred as unlocked from a cached JSON file. The reader queries firmware afresh and includes the Windows kernel's exact BootTime FILETIME to bind benchmark observations to a Windows session. Cached reports are historical evidence only.

For definitive live status, a trusted Windows hardware access path must perform bounded, read-only observations of the selector registers currently checked by `GuZ790ReadyForWindows()`: SS0 at BAR0+0x82381c must be 0x88888888; SS1 at +0x823820 must be 8. The full EFI predicate also checks chip, CPU state, high bits, readout, PLM and transaction invariants. A Windows implementation needs its own validated predicate because the NVIDIA driver can change non-selector registers. Do not blindly apply the entire pre-driver EFI predicate in Windows. No such live reader is installed by this change; no kernel driver, test signing, or Secure Boot changes are introduced. Driver reset event logs and ordinary power limits are not substitutes for selector observations.
